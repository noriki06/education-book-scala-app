判断の理由の正は `03_design.md` 付録B（ここに複製しない）。実装向けの画面・技術情報は `HANDOFF.md`。

## 落とし穴

- 01 の「受け取った要求」は**一括置換の対象外**（規約）。引用内の「開示」は誤混入ではなく、
  追加の要求で発注者自身が使った語（→ 01 質問リストの仮称行。業務語に昇格済み）
- 禁止語「レビュー」は、画面の導線名「この店をレビューする」と設計ドキュメントの査読の意味だけ例外
  （→ 03 用語表。「失敗」「行ける」にも同様の例外あり）
- 03 は800行級。編集時は節の境界を跨いだ混入に注意（判断30 の代償。実際に事故が起きた）
- Scala ブロックのコメント桁は**ブロックごとに**列を揃える。編集後に awk で検証する:
  `awk '/^```scala$/{f=1;b++} /^```$/{f=0} f && /\/\//{ idx = index($0, "//"); printf "b%d c%d\n", b, idx }' 03_design.md | sort | uniq -c`
- 提案の場面・枠数は 03 の導出ルール表が正（ルート2枠・開示後の詳細1枠。HANDOFF は画面配置のみ）
- `place` と `shopId` は排他。参照は `event → udb`・`shop → udb`・`event → shop` の一方向で、
  shop は event を一切知らない（逆流させたら判断31が壊れる）
