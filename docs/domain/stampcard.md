### 業務フロー（主語つき・例外つき）

[会員]
1. アプリを開く(スタンプカードも見れる)
2. メニューを見る（カテゴリごとに商品が並ぶ）
3. 商品を選び、オプション（サイズ・トッピング）を決めてカートに入れる
5. カートの中身と合計金額を確認する
6. 受け取り時間を選び、注文を確定する
7. 支払う
8. スタンプカードにスタンプが一つたまる
9. 店舗で受付番号を見せて商品を受け取る


[店舗スタッフ]
13. 入った注文を見る
14. 調理を始める        ← ここから会員はキャンセルできない
15. できあがったら「受け取り準備完了」にする
16. 会員に渡して「受け渡し完了」にする



[例外・ルール]
 - 売り切れの商品はカートに入れられない／注文確定時にも再チェックする
 - 営業時間外の店舗には注文できない
 - 調理開始後はキャンセルできない
 - 注文したあとに商品の価格が変わっても、注文の金額は変わらない
 - 商品が販売終了になっても、過去の注文履歴は正しく表示できる
 - スタンプが前回から１年以上の場合はスタンプカードは白紙に戻して一つ押す
 - 支払い後、スタンプ一つ押すが、そのあとキャンセルになったら、スタンプを消去
 - 店舗購入の際はスタンプカードをスキャンして、アプリのスタンプカードに反映させる
 - スタンプカードが10こ溜まっていればバーガーを一つを無料にする

### ふるい分けの表（エンティティ / 値オブジェクト / ただの属性 / 対象外 と、その理由

| 名詞 | 仕分け | 理由 |
|---|---|---|
| 会員 | **エンティティ** | ID で区別する。雛形の `User` をそのまま使う |
| 店舗 | **エンティティ** | 複数あり、それぞれ独立して管理される |
| 営業時間 | 属性 | 店舗の一部（開店時刻・閉店時刻） |
| カテゴリ | **エンティティ** | 表示順を持ち、本部が管理する。商品がぶら下がる |
| 商品 | **エンティティ** | 価格改定や販売終了があり、履歴を追う必要がある |
| 価格 | **値オブジェクト** | 590 円は 590 円。区別する意味がない |
| オプション（サイズ / トッピング） | **エンティティ** | 「選択肢のまとまり」と「1 つの選択肢」の 2 階層。商品から参照される |
| セット | 対象外（＝商品の一種） | 「セット」も 1 つの商品として扱い、中身の選択はオプションで表現する |
| 売り切れ | 属性 | ただし **店舗ごとに違う** ので、店舗と商品の組に対する状態になる |
| カート | **エンティティ** | 会員ごとに 1 つあり、中身が変わる |
| 数量 | **値オブジェクト** | 2 個は 2 個 |
| 合計金額 | 属性（ただし注文では保存する） | → [設計上の論点](#設計上の論点とその判断) で扱う |
| 受け取り時間 | 属性 | 注文の一部 |
| 注文 | **エンティティ** | 業務の中心。ID で追跡し、履歴として残す |
| 受付番号 | 属性（値オブジェクト） | 注文の公開用識別子。連番の ID は晒さない |
| 注文明細 | **エンティティ** | 1 注文に複数。1 行ごとに商品・数量・価格を持つ |
| 支払い | **エンティティ** | 外部サービスの取引 ID と結果を記録し、追跡する |
| 決済サービス | 対象外 | 外部システム。こちらのモデルではない |
| 注文の状態 | 属性（`EnumStatus`） | 注文の一部。遷移する |
| 調理 | 対象外（＝状態遷移） | 「調理中」という状態として表現する |
|スタンプ|**エンティティ**|日付を確認できる必要がある、いつどの注文かを確認可能|
|有効期限|**値オブジェクト**|スタンプを押した日から一年後|

### どのコンテキストに置くか（既存の common/menu / shop / sales に入れるか、新しく作るか。「誰が日常的に触るか」で判断し、理由を書く）
sales
理由：会員ごとに持つものであり、10個貯まれば購入時に使用できるものである
もし購入後キャンセルされたら、スタッフがスタンプを消去できる
そのため管理が会員と店舗スタッフである
スタンプの情報も注文情報（「いつ・どの注文で」）が必要なため

### 判断の記録（迷ったところと、その決着。02_BURGER_DOMAIN の「設計上の論点」と同じ形式で）

#### 「いま何個たまっているか」を数値として保存するか、押した記録（履歴）から数え上げるか。
押した記録を残したい、日にちをつけて次回の、スタンプの際の有効期限の確認するため

#### 有効期限「最後の注文から1年」は、どのタイミングで、どう判定するか。期限切れを表す状態を持つのか、日付から計算するのか。
アプリのスタンプカードを開いたタイミングで、日付で１年経過を確認してスタンプカードのスタンプ数を確認し、期限切れなら白紙に
購入者も今なら1個無料かどうかを確認するため


#### 注文がキャンセルされたら、スタンプはどうなるか（要求に書かれていません。あなたの判断と、その理由を書いてください）。
購入したら（アプリでのオンライン決済、店舗での決済）スタンプ一つ、途中キャンセルになったら、取り消しに
店舗での購入際に、受け取り完了でスタンプだとオペレーションが増えるので、
店舗支払いで途中キャンセルになったら、その注文情報にスタンプも入れて管理することで、スタンプも無効に
