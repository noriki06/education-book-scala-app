# <スタンプ> — 要件定義

## 受け取った要求
「注文1回につきスタンプを1個押したい。
10個たまったら、次の注文でハンバーガー1つが無料になる。
スタンプは店舗をまたいで共通。有効期限は最後の注文から1年。
お客さんは、いま何個たまっているかをアプリで見たい。」

### 追加の要求
「特典の種別ごとに有効期限を設定したい。
特典は全額無料・半額・金額割引（円）の3種類にしたい。特典だけの注文はスタンプ付与なし。
管理側で特典の利用実績を集計したい。」

## 確認したいこと（質問リスト）

### 当初の要求から出た確認事項

| 質問 | 今回の回答（仮） |
|---|---|
| スタンプ付与のタイミングは？ | 商品を受け取り完了した際に付与 |
| 1枚に何個貯めて、いつ特典になるか | リワードが定める必要スタンプ数を満たしたとき。1回の注文で使えるカードは1枚まで（当初は「10個で1つ無料」の固定だった） |
| カードの有効期限はどう決まるか | リワードごとに保有期間を持つ（例：通常＝1年、サマースタンプ＝3ヶ月）。カードができた日（＝会員がそのリワードで最初のスタンプを得た日）＋ その期間で確定（当初は「最後の注文から1年」の一律だった） |
| 特典はどんな種類があり、どの商品にどう適用されるか | 全額無料・金額割引（円）の2種類。リワードごとに1つ設定する。半額は対象商品の価格の半分を割引額として入れて表す。対象商品はリワードごとに1つ決める（商品側には何も持たせない）。対象商品1点に対して1つ適用する（当初は「ハンバーガー1つ無料」だけだった） |
| スタンプについて会員ができる操作は？ | 自身の有効スタンプ数・履歴の閲覧と、必要数が貯まった際の特典利用のみ |
| 業務の人はカードを何と呼んでいるか | 要求文にあるのは「スタンプ」のみ。カードの呼称は確認できていないため、仮に「ユーザーリワードカード」とする |

### 追加の要求で新しく出た確認事項

| 質問 | 今回の回答（仮） |
|---|---|
| 満杯になったカード（特典）の有効期限は | カードの有効期限 ＋ リワードが定める延長期間（例：＋1ヶ月）。早く貯めた会員ほど特典を使える残り期間が長くなる |
| 会員は複数のリワードのカードを同時に持てるか | スタンプを貯められるカードは常に1枚。ただし期間限定に参加している間は、それまで貯めていたカード（通常または別の期間限定）を**中断した状態で保持する**。中断中にさらに別の期間限定へ参加すると、中断中のカードが複数枚になることもある。並行して貯める（同時に2枚以上へスタンプを押す）ことはできない |
| 期間限定に参加したら、それまでに貯めたスタンプはどうなるか | それまで貯めていたカード（通常または別の期間限定）はそのまま中断して保持する。新しい期間限定のカードが別に1枚でき、スタンプは0個から数え直す。参加中のカードが終わったら、中断中のカードのうち最後に中断したものの続きから再開する（複数中断していれば後入れ先出し） |
| 中断していた分の有効期限はどうするか | 再開したときに、実際に中断していた日数を有効期限に加算する。中断中は期限切れにしない |
| 1人が同じリワードのカードを何枚まで作れるか | リワードごとに発行上限を持つ。通常スタンプは上限なし（満杯になったら2枚目・3枚目と続く）。期間限定のリワードは本部が開催ごとに決める枚数（今回の例では1枚）。発行上限に達したら、使い切っても期限切れになっても、それ以上は作れない |
| 特典のみの注文でもスタンプは付与されるか | 付与しない。特典対象以外の商品が1つでも含まれる注文には、通常どおり1個付与する |
| カードの状態はどう表すか | 収集中／特典獲得／使用済み／期限切れの4値の区分値で持つ。管理側が特典の利用実績を集計したいという要求があるため |

## 業務フロー

[本部]

1. リワード（名称・配布期間・必要スタンプ数・カードの有効期間・特典の延長期間・発行上限・特典の種類）を決める。〔追加要求〕

[会員]

2. アプリを開き、現在のスタンプ情報の表示をリクエストする。

[システム]

3. 会員のユーザーリワードカードの有効期限を確認する。
4. 期限を過ぎていれば有効スタンプ数を0として返す、
   期限内であれば有効なスタンプ数と、満杯のカードがあればその特典の有効期限をアプリに返す。〔追加要求で変更：特典の有効期限を返すようになった〕

[会員]

5. 画面に表示された「現在の有効スタンプ数」「カードの有効期限」「特典の有効期限」を確認する。〔追加要求で変更：特典の有効期限を表示するようになった〕
6. 商品をカートに入れる。（必要数のスタンプがたまっていれば、注文時に特典を選べる）
7. 注文を確定し、決済を完了する。

[システム]

8. 特典を利用した場合、注文確定のタイミングで、「特典獲得」の状態にある未使用のユーザーリワードカードのうち
   最も古い1枚を「使用済み」とする。〔追加要求で変更：状態が区分値になり、対象が複数枚から1枚選ぶ形になった〕
9. 特典を利用した注文がキャンセルされた場合、そのカードを「未使用」に戻す。〔追加要求で変更：状態を戻す操作になった〕

[店舗スタッフ]

10. 商品を会員に受け渡す。

[システム]

11. 受け渡し完了のタイミングで、特典対象以外の商品が含まれていれば、その注文にスタンプを1個発行する。〔追加要求で変更：特典だけの注文を除外するようになった〕
12. 押す先は、その会員が持つ、期限内・未使用・満杯でないカード。
    無ければ、配布期間内であることを確認して新しいカードを作る。〔追加要求で変更：配布期間の確認が入った〕

[会員]

13. 期間限定のリワードが開催中で、そのリワードの発行済み枚数が発行上限に達していなければ、参加するかどうかを選ぶ。〔追加要求〕

[システム]

14. 参加を選んだ場合、いま貯めているカードを中断し、期間限定のカードを新しく1枚作る。
    以後のスタンプは期間限定のカードに0個から貯める。〔追加要求〕
15. 期間限定のカードが満杯になるか期限切れになった時点で、中断中のカードのうち最後に中断したものを再開する。
    実際に中断していた日数を、そのカードの有効期限に加算する。〔追加要求〕

## 例外・ルール

### 当初の要求から決まっていたもの

- 全店舗の注文がスタンプ付与の対象になり、貯まったスタンプはどの店舗でも使える。
- スタンプの消費は注文確定時、付与は受け渡し完了時。
  消費は「使う宣言」なので早めに押さえ、付与は「受け取った事実」への対価なので後になる。
- 1枚に押せるスタンプはリワードが定める必要数まで。1回の注文で使えるカードは1枚まで。
  （当初は10個の固定だった）
- カードの有効期限は、できた日 ＋ リワードが定める有効期間で確定し、以後延長しない。
  （当初は「最後の注文から1年」で、注文のたびに延びる想定だった）

### 追加の要求で加わったもの

- 満杯になったカードの特典は、カードの有効期限 ＋ リワードが定める延長期間まで使える。
  早く貯めた会員ほど、使える残り期間が長い。
- 特典対象の商品しか含まない注文にはスタンプを付与しない。
  対象外の商品が1つでも含まれていれば1個付与する。
- 特典は対象商品1点に1つ。対象商品の代金を超えて割り引かない（マイナスにしない）。
  対象かどうかはリワード側で決める。リワードが対象商品を1つ持ち、商品側には何も持たせない。
- 新しいカードを作れるのは、リワードの配布期間中で、かつ発行上限に達していない場合に限る。
- 配布期間が終わっても、すでにできているカードは有効期限まで使える。終わるのは新規作成だけ。
- 1人が同じリワードのカードを何枚まで作れるかは、リワードごとに持つ発行上限で決まる。
  通常スタンプは上限なし。期間限定のリワードは本部が開催ごとに決める枚数（今回の例では1枚）。
- スタンプを貯められるカードは常に1枚。複数のリワードを並行して貯めることはできない。
  満杯になったカードは、使うまで複数枚たまることがある。
- 期間限定に参加すると、いま貯めているカード（通常スタンプ、または別の期間限定のカード）が中断される。
  中断中のカードにはスタンプを押さない。スタンプを貯められるカードは、中断していないカード1枚だけ。
- 中断中にさらに別の期間限定リワードへ参加することもできる。そのたびに、いま収集中のカードが
  新たに中断され、中断中のカードが積み重なる。中断枚数に上限は設けない。
- 中断中のカードは期限切れにしない。再開して中断日数を加算してから、期限を判定する。
  再開したときは、実際に中断していた日数を有効期限に加算する。
- 期間限定のカードが満杯または期限切れになったら、中断中のカードのうち**最後に中断したもの**を
  再開してスタンプを押す（後入れ先出し）。中断中のカードが複数あっても、戻る順番はこの1つに決まる。
  発行上限に達していれば、使い切ったか期限切れになったかは問わず、それ以上の再参加もできない。
