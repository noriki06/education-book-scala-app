# スタンプカード — 要件定義

> 有効期限の読み方を「最後の注文から1年（全スタンプ一律）」に取った版。

## 受け取った要求

> 「注文1回につきスタンプを1個押したい。
> 10個たまったら、次の注文でハンバーガー1つが無料になる。
> スタンプは店舗をまたいで共通。有効期限は最後の注文から1年。
> お客さんは、いま何個たまっているかをアプリで見たい。」

## 確認したいこと（質問リスト）

| 質問 | 今回の回答（仮） |
|---|---|
| 「有効期限は最後の注文から1年」とは、スタンプごとに押した日から1年で失効するのか、直近の注文から1年間はすべて有効なのか | **直近の付与日から1年**。新しくスタンプが押されるたびに、未使用スタンプ全体の期限が「その日から1年後」に更新される |
| 期限切れになったスタンプは、削除するのか記録として残すのか | 残す。集計から除外するだけで、いつ押されたかの記録は消さない |
| 注文がキャンセル・未受け取りになった場合、スタンプはどうするか | その注文で付与したスタンプを無効にする。その注文で特典に使ったスタンプがあれば、未使用に戻す |
| 特典を使った（無料の）注文でも、スタンプは付与するか | 付与する。通常の注文と同じ扱い |
| 無料で受け取れる商品の範囲は | ハンバーガーであればどれでもよい |
| 1日に押せる回数の上限はあるか | なし。注文1回につき1個 |
| 店舗スタッフが手動でスタンプを付与する機能は必要か | 将来必要になるが、**今回は作らない** → 03_design.md 付録A |

要求文の「有効期限は最後の注文から1年」は2通りに読めるため、最初に確認した。**この確認の結果が、以降の設計をほぼ決めている**（未使用スタンプの期限は常に同じ日になるため、期限は会員ごとに1つの値として扱える）。

## 業務フロー

```
[会員]
 1. アプリを開き、スタンプの状況を見る
 2. 商品をカートに入れ、注文を確定する
 3. スタンプが10個以上たまっていれば、注文時に「無料特典を使う」を選び、
    無料で受け取るハンバーガーを1つ選べる
 4. 支払う

[店舗スタッフ]
 5. 店頭注文の際は、会員が提示したコードをスキャンし、スタンプの付与を指示する

[システム]
 6. 支払いが完了したタイミングで、その注文にスタンプを1個記録する
 7. 特典を使った注文では、未使用のスタンプを古い順に10個選び、使用済みにする
 8. 注文がキャンセル・未受け取りになったら、その注文で付与したスタンプを無効にし、
    その注文で使用済みにしたスタンプがあれば未使用に戻す
 9. スタンプの状況を返すとき、直近の付与日から1年を過ぎていれば、
    未使用スタンプを数に含めない

[例外・ルール]
 - 有効期限は、新しくスタンプが押されるたびに「その日から1年後」へ一律で更新される
 - 期限切れの判定は、表示や注文確定のたびに行う。期限切れを記録として書き込む処理は持たない
 - 特典を使った注文でも、スタンプは1個付与される
 - キャンセル・未受け取りになった注文のスタンプは無効にする。削除はしない（履歴として残す）
 - 特典に使ったスタンプは、その注文がキャンセルされた場合のみ未使用に戻る
 - スタンプはどの店舗の注文でも付与され、どの店舗でも使える
```

主語を必ず書いている。誰の操作かが、次のページでコンテキストを決める材料になる。

例外・ルールは6行。うち2行目（期限切れを書き込まない）と4行目（削除しない）は、③のモデルの形をそのまま決める。
